# 현장 검증 (README 9.3장)

평일 퇴근 피크에 서울 쪽 주요 정류장에서 **앱이 낸 확률**과 **실제로 앉았는지**를 30–50건 기록한다.
대기 인원 모델(B안)을 사용자 단위로 직접 확인하는 유일한 방법이다. 데이터로는 "마지막 대기자가 앉았나"까지만 검증했다.

| 항목 | 내용 |
| --- | --- |
| 기간 | 11/17(월) – 11/26(수) 평일 17–20시 |
| 정류장 | 광교·서울역 (M5107), 신논현역·신분당선강남역 (5100), 잠실역 (1112) |
| 목표 | 30–50건. 한 번에 한 정류장, 같은 버스는 한 번만 |
| 테스트 기간 | 11/24–27 기록은 모델 최종 평가 뒤에만 열어 본다 |

## 한 건 기록하는 순서

1. **정류장에 도착하자마자** 예측을 저장한다. 도착 시각이 기록되고, 그 시각 기준의 확률이 남는다.
   ```bash
   ./capture.sh M5107 36          # 노선, station_seq (GET /stops 로 확인)
   ```
2. 내 앞에 **같은 노선을 기다리는** 사람 수를 센다 (`people_ahead`). 다른 노선 줄은 세지 않는다.
3. 앞차가 떠나는 것을 봤으면 그 시각을 적는다 (`prev_bus_departed`). 못 봤으면 비운다.
4. 다음 버스가 오면 차량번호, 도착 시각, 앞 전광판의 잔여석을 적는다.
5. 탔는지, 앉았는지 적는다. 못 탄 사람이 있으면 대략의 수를 적는다 (`left_behind`).

`capture.sh`는 서버의 추론 API를 부른다. 서버 밖에서는 터널이 필요하다: `ssh -N -L 8000:127.0.0.1:8000 bus`.
휴대폰으로 할 때는 SSH 앱(예: Termius)에서 같은 터널을 켜거나, 저장은 건너뛰고 시각만 정확히 적은 뒤
나중에 `arrived_at`을 넣어 다시 계산한다. 이렇게 다시 계산할 때는 그 시각 이후 관측이 섞이지 않도록 서버가 아니라
`src.live`로 그 시각까지의 관측만 써서 계산해야 한다.

## 분석할 것

- `app_my_seat`의 보정: "60%"라고 한 경우 실제로 60% 앉았나 (표본이 적으므로 0–50%, 50–80%, 80–100% 세 구간)
- `people_ahead` vs `app_people_ahead`: 대기 인원 모델의 오차. 특히 앞차가 만석으로 떠난 경우
- `display_seats` vs 모델이 쓰는 API 잔여석: 하차 많은 정류장에서 차이 (DECISIONS.md 남은 일)

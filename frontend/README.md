# 경희 통학버스 좌석 전망 · 프론트엔드

Expo / React Native / TypeScript(strict) / Expo Router / TanStack Query 기반 iOS·Android 앱입니다. 기본값은 mock이며 백엔드, 인증키, 지도 없이 전체 조회 흐름을 사용할 수 있습니다. 원본 작업 문서와 HWP는 수정하지 않았습니다.

## 실행

```sh
cd frontend  # AIP_project에서 실행할 때
npm ci
npm start
```

터미널 QR을 호환되는 Expo Go로 스캔합니다. 설치된 SDK는 `package.json`/잠금 파일을 기준으로 합니다(SDK 58). 스토어 Expo Go가 SDK 58을 아직 지원하지 않으면 호환 개발 빌드/시뮬레이터가 필요합니다. `npm run ios`는 전체 Xcode와 iOS 시뮬레이터, `npm run android`는 Android SDK와 에뮬레이터 또는 USB 기기가 필요합니다. 웹사이트로 대체한 앱이 아닙니다.

브라우저에서 미리 보려면 `npm run web`을 실행하세요. 웹 미리보기에 필요한 `react-native-web`, `react-dom`, `@expo/metro-runtime`도 설치되어 있습니다. 패키지 설치 후 이미 실행 중인 서버에서 모듈 오류가 계속되면 Ctrl+C로 종료한 뒤 `npm run web -- --clear`로 캐시를 비우고 재시작하세요. 모바일 앱은 동일한 코드로 유지됩니다.

기본 실행에는 환경 파일이 필요하지 않습니다. 필요 시 `.env.example`을 `.env.local`로 복사하고 Expo 개발 서버를 재시작하세요. `EXPO_PUBLIC_*` 값은 앱에 공개됩니다. 비밀키를 넣지 마세요.

지도는 앱의 기본 홈입니다. 기본 모드에서도 경기버스 공식 노선과 정류장 좌표를 실제 카카오맵 위에 표시합니다. 웹·네이티브 키 등록, 개발 빌드, 실제 노선/GPS 서버 연결 방법은 [카카오맵 연결 안내](docs/kakao-map.md)를 참고하세요. 지도 SDK와 데이터 수신 코드는 연결되어 있으며, 실제 지도 표시는 카카오 키·플랫폼 등록이 필요합니다. 실시간 버스 이동 표시는 별도의 GPS API 연결이 필요합니다.

## 현재 디자인 · 지도 중심 홈 (2026-11-12)

사용자가 제공한 네 장의 이미지에 맞춰 기본 진입을 `app/index.tsx` → `src/features/map-home/home.tsx`로 변경했습니다.

- 지도 홈: 노선별 색상 선, 정류장 이름·좌석 확률, 현재 잔여석, 1/5/10석 전환, 도착 순서 카드.
- 버스 상세: 선택 차량 강조, 현재 관측 좌석과 도착 시 누적 확률 막대, 정류장별 예측.
- 정류장 비교: 실제 도보 경로가 있고 제시간에 도착하며 기다리는 것보다 빠른 후보만 추천.
- 시간대 전망: 시간별 확률, 70% 기준선과 현재 시각, 도착 예정 버스.

이미지의 구성은 유지하고 Flame 색상으로 바꿨습니다. 노선 구분색은 5100 #EC0000(빨강), M5107 #245EC7(파랑), 1112 #087F72(청록)입니다. 지도 노선은 사용자의 구분 요청에 따라 별도 색을 쓰며, 나머지 UI는 Flame 팔레트를 유지합니다. 확률은 빨강/Madrid/Rio, 정보 카드는 Sky를 사용합니다.

기본 모드에서도 **실제 카카오맵**에 5100·1112·M5107의 공식 도로 경로와 실제 정류장을 표시합니다. 예시 노선도 전환은 제거했습니다. 좌석 확률·도착 차량 예시는 상단의 **실제 노선 · 예시 확률**로 구분합니다. 실시간 GPS는 합성하지 않으며, 실제 운행 서버 연결이 필요합니다.

노선 데이터는 GBIS 공개 지도에서 내려받은 스냅샷입니다. 상하행을 구분하고 경유 전용 지점은 탑승 정류장에서 제외했습니다. 데이터와 갱신 방법은 [공식 노선 자료](docs/gbis-routes.md)를 참고하세요.

최신 실제 화면: [정류장·노선](docs/screenshots/real-kakao-M5107.png), [전체 노선](docs/screenshots/real-kakao-overview.png), [귀환 방향](docs/screenshots/real-kakao-return.png).

## 부가 화면

- 홈: 새 조회, 즐겨찾기 조회/삭제, 개발 전용 시나리오 선택기.
- 선택: 1112 / 5100 / M5107 → 국제캠퍼스/서울 방향 → 검색 가능한 정류장. 동일 ID도 방문 순번으로 구분합니다. 노선/방향 선택 화면에는 이전 정류장 선택 상태 자체를 보관하지 않습니다.
- 결과: 실제 응답 수만큼 최대 3대, ETA/예상 표시, 모델 예측·과거 빈도 출처, 1/5/10석 이상 누적 확률, 개별 분포 오류, 새로고침, 즐겨찾기.
- 시간대 전망: 특정 차량과 별도 화면, 날짜 선택, 결측은 ‘예측 없음’, 수치 텍스트와 막대.
- 과거 기록: 날짜 및 오전/오후 필터, 관측 시점 구분, 좌석 구간, 수집 범위 밖/빈 상태.
- 대안 정류장: 같은 노선·방향 후보, 거리 종류, 도보 시간, ETA, 서버 판단과 추천 보류 사유.

즐겨찾기는 AsyncStorage에 `{version:1,items:Selection[]}`으로 저장합니다. 손상/버전 불일치는 안내하고 앱을 계속 실행합니다. 삭제된 정류장은 재선택을 요구합니다. 실제 기기 재시작 복원은 아래 수동 검증 항목입니다.

## 예시 모드와 가정

모든 정류장·차량·운행 ID는 `mock-` 접두어를 사용합니다. 노선명 외의 운행정보는 공식 데이터가 아닙니다. 좌표는 모두 null입니다. 데모 시각은 **2026-11-04 08:00 Asia/Seoul**, 기록 날짜는 11월 4일뿐이며 날짜를 바꿔도 기록을 복제하지 않습니다. 기본 분포의 표시값은 **92% / 71% / 38%**입니다.

홈 개발 도구에서 정상 3대, 1대, 2대, 차량 없음, 확률 0/null, 일부 카드 오류, 오래된 데이터, HTTP 실패, 기록 없음, 잘못된 합, 대안 없음/ETA 불명, 직선거리, 위치 권한 거부, 저장 손상, 시간대 전망 실패를 선택합니다. 개발 도구는 `__DEV__`와 mock 모드에서만 보입니다.

- HTTP 실패 + 캐시: 정상 결과 조회 → 홈으로 복귀 → HTTP 실패 선택 → 같은 조합 조회. 캐시가 있으면 최신 정보 아님을 표시합니다. 새 조합은 재시도 오류 화면입니다.
- 부분 실패: 시간대 전망 실패에서도 차량 결과/과거 기록은 정상입니다.
- 손상 시나리오는 실제 사용자 저장소를 덮어쓰지 않고 같은 디코더에 손상 문자열을 주입합니다.
- 위치 거부 시나리오는 안내 상태 재현입니다. 현재 위치 권한을 실제로 요청하는 기능은 P1 미연결입니다.
- 자동 재시도는 1회, 수동 갱신 지원. API 차량 결과만 앱 활성 중 30초 갱신합니다. mock 자동 갱신은 없습니다.

## API 전환

```dotenv
EXPO_PUBLIC_DATA_MODE=api
EXPO_PUBLIC_API_BASE_URL=https://your-service.example
```

주소가 없거나 실패하면 설정/네트워크 오류를 표시하며 mock으로 전환하지 않습니다. 실제 서버는 구현하지 않았습니다. 경로·필드·예시는 [API 계약 초안](docs/api-contract.md)에 있습니다. 응답 구조는 Zod로 검증하고, 분포의 범위/합은 공통 변환 함수에서 검증합니다. 0은 유효하며 null과 구분합니다. 실제 모드는 기기 시계와 서울 시간대 표시를 사용합니다.

## 코드와 디자인 적용 지점

`app/`은 라우팅, `src/features/`는 화면/상태/query hook, `src/data/`는 mock/HTTP adapter, `src/domain/`은 계약·검증·변환, `src/mocks/`는 고정 fixture와 주입 가능한 기준 시계입니다. `src/theme/index.ts`에서 색·타이포·간격·모서리 토큰을 바꾸고 `src/components/ui.tsx`에서 카드/버튼/막대를 조정할 수 있습니다. 최종 화면 배치는 `app/index.tsx`, `app/select.tsx`, `src/features/result-screen.tsx`에서 변경합니다.

## 지도 및 미연결 항목

현재 지도 영역에는 설정 안내와 정류장 목록을 제공합니다. P0에 지도 SDK가 필요하지 않습니다. P1에서 모바일 지도 SDK/플랫폼별 키·빌드 설정과 공식 정류장 좌표를 제공한 뒤 마커·목록 동기화를 구현해야 합니다. 좌표가 없는 정류장에는 임의 마커를 넣지 마세요. 위치 버튼을 구현할 때만 권한을 요청하고 거부 시 수동 목록을 유지합니다.

실제 서비스 연동에는 API 주소/확정 계약, 실제 노선·방향 코드, 정류장 ID/방문 순번/좌표, 수집 기간 메타데이터, freshness 기준, 대안 도보 경로/도달 판단이 필요합니다. 로그인, 모델 학습, 수집기, 클라우드 배포는 범위에 포함하지 않았습니다.

## 검증

```sh
npm run typecheck
npm run lint
npm test
npm run test:ui
npx expo install --check
npx expo export --platform ios --platform android --output-dir dist
```

`npm test`는 분포·누적 확률·관측 좌석·서울 시간·즐겨찾기·요청 격리·시나리오·HTTP adapter를 검증합니다. 화면 테스트는 React Native 테스트 렌더러를 사용하며 실제 OS 실행을 대신하지 않습니다.

실제 수행 결과와 제한은 [검증 기록](docs/verification.md)을 참고하세요. 기기에서 추가 확인할 항목: 두 플랫폼 실행, Android 뒤로가기, 작은 화면/긴 정류장명/큰 시스템 글꼴, 검색 키보드, VoiceOver/TalkBack, 앱 강제 종료 후 즐겨찾기 복원. 스크롤·안전 영역·줄바꿈·최소 48pt 터치 영역·접근성 레이블은 코드에 적용했습니다.
